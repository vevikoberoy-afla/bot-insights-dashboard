# Chatwoot — `javascript/v3/` Knowledge Map

## What Is This?
The **newer Vue 3 auth/onboarding application** — a separate mini-SPA covering login, sign-up, and account onboarding flows. It was extracted from the main dashboard into its own bundle (`v3app.js`) as part of a modernization effort (hence "v3"). Uses Pinia instead of Vuex.

> **Vittain context:** Vittain has its own auth system at `/auth/login` and `/auth/register` built with Next.js + Supabase Auth. Chatwoot's v3 auth is only relevant when agents log into the **embedded Chatwoot iframe** — they authenticate directly with the Chatwoot instance, not through Vittain's auth.

## Routes (`v3/views/routes.js`)

| Route | View | Description |
|---|---|---|
| `/app/login` | `login/` | Email + password login |
| `/app/auth/sign_up` | `auth/` | Create new account |
| `/app/auth/reset_password` | `auth/` | Password reset request |
| `/app/auth/password/edit` | `auth/` | Set new password (from email link) |
| `/app/onboarding` | `onboarding/` | Step 1: Account details (name, timezone) |
| `/app/onboarding/inbox-setup` | `onboarding/` | Step 2: Create first inbox |

## Views

### `views/login/`
Login page features:
- Email/password form
- "Forgot password" link
- Google OAuth button (if enabled)
- SSO/SAML login option (if configured)
- "Remember me" checkbox

### `views/auth/`
- Sign-up form: name, email, password, account name
- Password reset: email input → sends reset link
- Password edit: new password + confirm (accessed via email link token)

### `views/onboarding/`
Two-step onboarding flow triggered after sign-up:

**Step 1 — Account Details:**
- Account name
- Language selection
- Timezone selection

**Step 2 — Inbox Setup:**
- Choose channel type (Website Widget, WhatsApp, Email, etc.)
- Configure the chosen channel
- Invite teammates (optional)
- This is how the first Chatwoot inbox gets created

## Components

### `components/Form/`
Reusable form field components used across login/signup:
- Input with label + validation
- Password input with show/hide toggle
- Error message display

### `components/GoogleOauth/`
Google OAuth sign-in button component:
- Initiates Google OAuth flow
- Handles callback and token exchange with Chatwoot backend

### `components/SnackBar/`
Toast notification component for success/error feedback (e.g., "Password reset email sent").

---

## Store (`v3/store/`)
Uses **Pinia** (not Vuex). Stores:
- Auth state (current user, token, errors)
- Onboarding progress state
- Account creation state

---

## API (`v3/api/`)
Auth-specific API calls:
- `POST /auth/sign_in` — login
- `POST /auth/sign_up` — register
- `POST /auth/password` — request password reset
- `PUT /auth/password` — update password
- `GET /auth/oauth/google` — initiate Google OAuth

---

## Relationship to Main Dashboard
After successful login or onboarding:
- v3 app redirects to → `/app/accounts/:accountId/dashboard`
- That URL is handled by the main `dashboard.js` bundle
- Session is maintained via cookie/token shared between the two bundles

## Vittain Agent Login Flow

```
Agent opens Vittain dashboard → clicks "Live Messages"
  └── /messages/live page loads
        └── <iframe src="CHATWOOT_URL/app/accounts/1/conversations" />
              └── If not logged in → Chatwoot redirects inside iframe to:
                    CHATWOOT_URL/app/login   ← v3/views/login/ renders here
              └── Agent logs in with Chatwoot credentials
              └── Redirected back to conversations inbox
```

> This means agents need **two logins**: Vittain account (via Supabase) and Chatwoot account (via v3 auth). To avoid this friction, Chatwoot supports SSO — could be configured so agents log in once.
